## Context

在《鬥陣特工名片》（OWCard）中，常用英雄展示區的三個卡槽原本共用一個全域淡黃偏白背景（`bg-[#fdfaf3]/60`），且缺乏獨立背景與漸層。本設計為了解決此痛點，引入「每個卡槽獨立渲染專屬背景」的架構，並透過智慧主題引擎動態解析 51 位英雄的主色調與定位氣質。

## Goals / Non-Goals

**Goals:**
* **千人千面、獨立渲染**：名片中的三個常用英雄卡槽各自擁有獨立的、根據裝填英雄動態解析的極簡美學背景。
* **雙軸智慧主題引擎**：藉由「代表色 (Colors) + 定位 (Role)」雙軸，由坦克（六角盾牌）、傷害（凌厲斜線）、輔助（圓潤光環）三套美學模具自動推導 51 位英雄的背景。
* **高質感視覺深度**：採用線性漸層底色、氛圍徑向光暈、定位幾何圖形與科技網格的 5 層堆疊系統，柔化立繪邊緣，打造立體懸浮感。
* **名字標籤對比度適配**：根據卡槽背景的深淺，自動調整 Hero Name Badge 的字體、背景與細邊框配色對比度。
* **懸浮微互動**：當滑鼠移入卡槽時，其背景幾何圖形套用平滑的 `scale(1.05)` 位移與過渡效果。

**Non-Goals:**
* 不使用任何外部背景點陣圖片，完全以 CSS (Tailwind) 與 SVG 等向量幾何代碼實現。
* 不引入重量級的 JS 動畫庫（如 Framer Motion），保持最純粹的 CSS GPU 加速動畫，確保低階設備流暢度。

## Decisions

### 決策 1：雙軸智慧主題引擎 (Bi-Axis Theme Engine)
* **背景與痛點**：遊戲內有 51 位英雄，如果為每個人單獨手動編寫特製的幾何 SVG 背景，將造成程式碼極其臃腫（2000+行），且未來維護性與擴展性極差。
* **方案**：採用「代表色對照字典 (`HERO_COLORS`)」搭配「定位幾何模具 (`Role Mold`)」雙軸推導演算法。
  * 只需要整理出一個 51 位英雄主要色彩 Hex 對照表（共約 50 行），智慧背景元件會根據英雄的 `role` 類型，動態套用特定的幾何構圖。
* **理由**：既做到了「千人千面」的色彩個性化，又保起了「程式碼的高度共用與極簡性」。若遊戲未來新增第 52 位新英雄，開發者只需在其色彩表中補上一行，引擎便能完美適配。

### 決策 2：純 CSS / Tailwind 與向量幾何 (Tailwind + Inline SVG)
* **方案**：不使用 WebP 或 PNG 背景圖，所有的背景漸層、徑向光暈、幾何形狀（圓弧、平行線、六角形）全部使用 CSS Linear/Radial Gradient 以及 Tailwind 類別動態渲染。
* **理由**：
  * **零下載開銷**：省去背景圖片下載的網路延遲與流量，卡片渲染完全是瞬時的。
  * **極致響應式與清晰度**：幾何圖案與漸層在任何高解析度螢幕上均維持完美銳利度，不模糊、不失真。

## Risks / Trade-offs

* **[Risk 1: 配色衝突或名字標籤看不清]**：部分英雄主色極亮（如慈悲的亮黃），部分極暗（如死神的深紫黑），若名字標籤（Name Badge）配色固定，在極亮/極暗背景下會喪失對比度。
  * **[Mitigation]**：在色彩配置中加入 `theme: 'light' | 'dark'` 標記，若為 'dark'，名字標籤自動採用高亮或白色的細邊框與字體，反之採用沉穩深色，確保在任何色彩碰撞下都有完美的可讀性。
* **[Risk 2: 圖片加載失敗時的邊界狀態]**：立繪去背圖片載入失敗時會回退到預設的 `silhouette.png` 剪影。
  * **[Mitigation]**：回退的剪影同樣完美融入我們渲染的專屬幾何背景中，維持高雅感，不發生視覺碎裂。
