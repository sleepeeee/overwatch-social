# After Midnight — 網站圖片模糊問題與 SEO 關鍵字優化診斷報告

> **診斷日期**：2026-06-11
> **適用專案**：After Midnight 玩家名片展示館 (Next.js & Vercel 部署)
> **目的**：解決玩家名片與圖片在不同設備間歇性模糊的問題，並依照圖片真實用途修正 `alt` 屬性。注意：通用玩家頭像不是鬥陣英雄圖，不能硬塞「鬥陣特攻」關鍵字。

---

## 🔍 問題描述與現象
在網站運行過程中，有時會觀察到以下現象：
1. **間歇性模糊**：同一個網頁，有時候打開圖片是清晰的，有時候卻是模糊的（通常在第一次載入時模糊，重新整理後變清晰）。
2. **跨設備差異**：在一般桌上型電腦螢幕上看很正常，但在 **iPhone、iPad 或高階 Android 手機**上觀看時，圖片邊緣有明顯的模糊或顆粒感。

---

## 🛠️ 兩大技術主因分析

### 原因一：Retina/行動裝置螢幕的「設備像素比 (DPR)」適配問題
現代智慧型手機與高階螢幕（如 Apple Retina 顯示器）的物理像素密度非常高。

* **運作機制**：
  * **一般電腦螢幕 (DPR = 1)**：在網頁上顯示 `150px` 寬度的圖片，剛好填滿螢幕的 150 個物理像素點，看起來清晰。
  * **手機/Retina 螢幕 (DPR = 2 ~ 3)**：在畫面上雖然也是 `150px` 寬，但因為螢幕密度極高，瀏覽器實際上需要 `300px` 甚至 `450px` 的圖片解析度才能填滿物理像素。如果回傳的圖片剛好是 150px，瀏覽器被迫將其**拉大 2-3 倍**渲染，就會看起來非常模糊。
* **診斷結論**：當前專案部分圖片（如英雄縮圖或卡片立繪）可能因為原圖尺寸、CSS 放大或 DPR 倍率不足，在手機端觀看時產生模糊。通用玩家頭像需要獨立檢查，不應和鬥陣英雄圖片混為同一類。

---

### 原因二：Vercel / Next.js 圖片優化快取延遲 (Image Cache Processing)
當圖片使用 `next/image` 時，第一次訪問新網頁、或快取過期時，可能會觸發 Next.js 的動態圖片處理機制：

1. **快取未命中 (Cache Miss)**：
   第一位訪客進來時，Vercel 伺服器需要在背景下載原圖並進行 WebP 壓縮與重設尺寸。為了防止網頁加載被卡住，Next.js 會先回傳一個低解析度的臨時圖（Blur Placeholder）或縮圖，此時訪客會看到**模糊的圖片**。
2. **快取命中 (Cache Hit)**：
   一旦伺服器背景處理完成，高畫質 WebP 就會被快取在 Vercel Edge CDN。此後所有訪客（或是重新整理網頁）就能瞬間拿到高畫質 WebP，圖片**回復清晰**。

> **目前專案狀態補充**：`OWCard`、玩家詳情頁與 Profile 編輯器中的多數英雄圖片目前使用原生 `<img>`，不是 `next/image`。因此這個原因只適用於已使用 `next/image` 的區塊，例如 `LuckyAlly`，不能直接套用到所有英雄立繪。

## 圖片分類圖鑑：先分清楚裝備欄

| 圖片類型 | 目前路徑 | 正確身份 | `alt` 策略 |
|---|---|---|---|
| 通用玩家頭像 | `public/images/avatars/*` | 玩家帳戶頭像，跨遊戲通用 | 使用「玩家頭像」語意，不加入「鬥陣特攻」 |
| 鬥陣英雄全身立繪 | `public/images/heroes/full/*` | 玩家名片中的英雄展示圖 | 可加入「鬥陣特攻英雄」關鍵字 |
| 鬥陣英雄縮圖 | `public/images/heroes/avatars/*` | 玩家所選常用英雄縮圖 | 可加入「常用英雄縮圖」語意 |
| 其他遊戲角色縮圖 | `public/images/heroes/avatars/val_*`、`lol_*` | Valorant / LoL 角色縮圖 | 使用各遊戲自己的語意，不加入鬥陣關鍵字 |

## ✍️ SEO 與無障礙 `alt` 優化提案
Google 爬蟲無法直接解讀圖片內容，螢幕閱讀器也會依賴 `alt` 屬性。建議依照圖片真實身份修正，不要全站套同一套關鍵字。

### 1. 玩家名片上的英雄全身立繪
修改檔案：`src/components/OWCard.tsx`
* **修改前**：
  ```tsx
  <img src={`/images/heroes/full/${heroInfo.id}.png`} alt={heroInfo.name} />
  ```
* **修改後**（融入繁體關鍵字）：
  ```tsx
  <img src={`/images/heroes/full/${heroInfo.id}.png`} alt={`《鬥陣特攻》英雄 ${heroInfo.name} 角色名片立繪`} />
  ```

### 2. 動態玩家頁面的常用英雄縮圖區
修改檔案：`src/app/player/[id]/page.tsx`
* **修改前**：
  ```tsx
  <img src={`/images/heroes/avatars/${hero.id}.png`} alt={hero.name} />
  ```
* **修改後**：
  ```tsx
  <img src={`/images/heroes/avatars/${hero.id}.png`} alt={`鬥陣特攻英雄 ${hero.name} 常用英雄縮圖`} />
  ```

### 3. 通用玩家頭像
修改檔案：`src/components/InteractiveAvatar.tsx`

通用玩家頭像不是鬥陣英雄圖，不應加入「鬥陣特攻」關鍵字。

* **建議語意**：
  ```tsx
  <img src={currentAvatarUrl} alt={`玩家頭像：${displayName}`} />
  ```

## 💡 具體技術排查與解決方案建議

1. **為行動裝置調整 `sizes` 屬性 (針對使用 `next/image` 的地方)**：
   在 `<Image>` 元件中明確給予 sizes 屬性，例如：
   ```tsx
   sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
   ```
   這能引導 Next.js 根據訪客設備的螢幕解析度（DPR）自動回傳 2 倍或 3 倍大小的優化圖片。
2. **調高圖片壓縮品質**：
   Next.js 預設的圖片優化品質是 `75`。對於遊戲卡片等有細緻立繪的網站，建議將 quality 調高至 `85` 或 `90`，以防止細節被過度壓縮產生糊邊：
   ```tsx
   quality={85}
   ```
3. **限制通用玩家頭像解析度**：
   若未來開放玩家自己上傳頭像，建議限制來源圖片解析度不得低於 `400x400` 像素，並在後端裁切為適當的正方形尺寸。目前專案使用預設通用頭像資產，沒有玩家自由上傳流程。

4. **優先排查 CSS 放大**：
   對英雄立繪先檢查 `max-w`、`max-h`、`scale()` 與容器高度。若圖片被 CSS 放大超過原始素材可承受範圍，即使不使用 `next/image` 也會變模糊。
